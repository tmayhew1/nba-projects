● An NBA analytics companion

A points-equivalent framework for measuring NBA player value.

Trey’s NBA Stats Stuff is an interactive R Shiny app that re-expresses every box-score contribution — scoring volume, shooting efficiency, playmaking, defensive event creation, ball security, and rebounding — in a single common unit: points added relative to a league-average minute. This document explains the framework, defines every component, and gives a tab-by-tab guide to the analytical conclusions the app supports.

1. Overview #

The application addresses one question: how much, in points, did this player contribute that an average player at the same minutes load would not have? It then unpacks that headline number across every dimension of the box score, surfaces the result through six interactive tabs, and provides peer-relative context at the league, season, career, and single-game levels.

The app is a single-file R Shiny application backed by a daily Basketball-Reference scrape. Player totals back to the 1949–50 season are normalized against per-minute league averages to produce a vector of points added components. Those components are then rolled up into a single valueAdd figure or visualized individually so the user can see where a player’s contribution comes from, not just how much there is.

This documentation is organized as follows. Section 2 motivates the Value Added framework. Section 3 specifies the math. Section 4 describes each tab — what to put in, what comes out, and what conclusions are licensed. Sections 5 through 9 cover a worked example, the variable glossary, the data pipeline, methodological limitations, and possible extensions.

Audience The intended reader is a basketball-literate analyst who is comfortable thinking about per-minute rates and league-relative baselines but who has not seen this specific framework before. Where the math becomes opinionated — e.g., the assist-credit weighting or the rebound-attribution scheme — the choice is flagged explicitly so the user can decide whether to accept or critique it.

2. The Value Added concept #

2.1 Why a single unit?

Box-score statistics are not commensurable. An assist is not a rebound, a steal is not a free throw, and a turnover is not a missed three. Comparing two players requires either (a) collapsing everything into an opaque single number (PER, BPM, Win Shares) or (b) presenting an array of stats and asking the reader to weight them. The first sacrifices interpretability; the second sacrifices decisiveness.

The Value Added framework takes a third path: it converts every box-score event into the same unit — points scored above a league-average player at the same minutes — using only league-wide baselines that the data themselves provide. The result is additive (the components sum to the headline), interpretable (every term has units of points), and decomposable (the user can always ask which component is doing the work).

2.2 Three claims that organize the framework

  1. Every contribution can be expressed in points. Scoring is already in points. Assists become points by way of expected made baskets they create. Steals and blocks become points via the value of the possession denied. Rebounds become points by way of the possession secured (or surrendered) and that possession’s expected value. Turnovers are negative points by the same possession logic.
  2. The right baseline is “the league’s average minute, scaled to this player’s minutes.” Comparing a player to the league average per game double-counts minutes (a 36-minute starter is not 1.0× a 24-minute reserve). Comparing to a positional baseline imports a structural assumption the data do not require. The app uses per-minute league averages, scaled by the player’s actual minutes, so the comparison is “you played MP minutes; what would the league have produced in those minutes?”
  3. Volume and efficiency are separable, and both are real. A player who scores a lot at average efficiency adds value (they free other players from the burden). A player who scores at high efficiency on low volume also adds value (every shot is positive expectancy). The framework gives them separate components — vaPTSv for volume and PTSAdd for efficiency — rather than netting them out.
The headline equation

For a player’s season, the framework computes:

$$ \texttt{valueAdd} = \underbrace{\texttt{vaPTSv}}_{\text{scoring volume}} + \underbrace{\texttt{PTSAdd}}_{\text{scoring efficiency}} + \underbrace{\texttt{vaAST}}_{\text{playmaking}} + \underbrace{\texttt{vaSTL} + \texttt{vaBLK}}_{\text{defensive events}} + \underbrace{\texttt{vaTOV}}_{\text{ball security}} + \underbrace{\texttt{vaDRB} + \texttt{vaORB}}_{\text{rebounding}} $$

Every term is in points. Positive means above league average; negative means below.

3. Methodology #

This section specifies the formulas. Each component is derived per season; per-game versions are obtained by dividing by games played (G). The implementation lives in totals_collect.R (season-level aggregates) and is recomputed inline in app.R for live game-log views.

3.1 League baselines

For every season $y$ the app computes the following league-wide quantities, stored in Complete Data/avgsSummary.csv:

SymbolDefinitionInterpretation
laPTSperMmedian of PTS / MP across qualifying playersthe typical points produced per minute
laASTperM, laSTLperM, laBLKperM, laTOVperM, laDRBperM, laORBperMmedian of the corresponding rateper-minute league baselines for each event type
la2P., la3P., laFT., laFG.league sums — e.g. $\sum X3P / \sum X3PA$league shooting accuracy at each level
laPTSperMake$(3 \cdot X3P + 2 \cdot X2P) / (X3P + X2P)$average points per made field goal
laPTSperPoss$\dfrac{\text{PTS}}{X2PA + X3PA + \text{TOV} + \text{FTA}/2.1}$league points per possession; for pre-1973 seasons (when TOV is missing) it is imputed from a linear regression on laPTSperM and laTRBperM.
laORBrate, laDRBrate$\text{ORB}/\text{TRB}$, $\text{DRB}/\text{TRB}$fraction of all rebounds that are offensive vs. defensive

The use of medians for per-minute rates (rather than means) is deliberate: it suppresses the influence of outlier high-volume seasons and gives a baseline closer to the typical NBA player’s footprint per minute on the floor.

3.2 Component formulas

For a player-season with statistics $\{\text{PTS, AST, STL, BLK, TOV, DRB, ORB, MP}\}$ and the league baselines above, the components are:

Scoring — volume (vaPTSv)
$$\texttt{vaPTSv} = \left( \tfrac{\text{PTS}}{\text{MP}} - \texttt{laPTSperM} \right) \cdot \text{MP}$$ How many extra points the player put on the board per minute, scaled by minutes played. A high-usage scorer sits well above zero; a low-usage role player sits near or slightly below zero.
Scoring — efficiency (PTSAdd)
Computed from three shot-type components — each is points added by shooting better than league average on the player’s own attempted volume: $$ \texttt{X2PAdd} = (X2P. - \texttt{la2P.}) \cdot X2PA $$ $$ \texttt{X3PAdd} = (X3P. - \texttt{la3P.}) \cdot X3PA $$ $$ \texttt{FTAdd} = (FT. - \texttt{laFT.}) \cdot FTA $$ $$ \texttt{PTSAdd} = 2 \cdot \texttt{X2PAdd} + 3 \cdot \texttt{X3PAdd} + \texttt{FTAdd} $$ Each *Add is the number of extra makes a player generated above what a league-average shooter would have produced on the same attempt total. PTSAdd converts those extra makes back into points.
Playmaking (vaAST)
$$\texttt{vaAST} = \left( \tfrac{\text{AST}}{\text{MP}} - \texttt{laASTperM} \right) \cdot \text{MP} \cdot \texttt{laPTSperMake} \cdot (1 - \texttt{laFG.})$$ An assist is credited the value of the made field goal it created (laPTSperMake), but only the marginal portion above what would have happened anyway: a fraction $(1 - \texttt{laFG.})$ representing baskets that would not have been made without the pass. This is an opinionated weighting and is documented as such.
Defensive events (vaSTL, vaBLK)
$$\texttt{vaSTL} = \left( \tfrac{\text{STL}}{\text{MP}} - \texttt{laSTLperM} \right) \cdot \text{MP} \cdot \texttt{laPTSperPoss}$$ $$\texttt{vaBLK} = \left( \tfrac{\text{BLK}}{\text{MP}} - \texttt{laBLKperM} \right) \cdot \text{MP} \cdot \texttt{laPTSperPoss} \cdot \texttt{laDRBrate}$$ A steal terminates a possession outright, so it is credited a full laPTSperPoss. A block, by contrast, only produces a stop if the defense secures the rebound — about laDRBrate of the time — so its credit is discounted accordingly.
Ball security (vaTOV)
$$\texttt{vaTOV} = -1 \cdot \left( \tfrac{\text{TOV}}{\text{MP}} - \texttt{laTOVperM} \right) \cdot \text{MP} \cdot \texttt{laPTSperPoss}$$ Sign-flipped so that fewer turnovers than league average contributes a positive number. The penalty per excess turnover is one expected possession.
Rebounding (vaDRB, vaORB)
$$\texttt{vaDRB} = \left( \tfrac{\text{DRB}}{\text{MP}} - \texttt{laDRBperM} \right) \cdot \text{MP} \cdot \texttt{laPTSperPoss} \cdot \texttt{laORBrate}$$ $$\texttt{vaORB} = \left( \tfrac{\text{ORB}}{\text{MP}} - \texttt{laORBperM} \right) \cdot \text{MP} \cdot \texttt{laPTSperPoss} \cdot \texttt{laDRBrate}$$ Each rebound is credited a possession, but discounted by the probability the team would not have secured the rebound otherwise. A defensive rebound is the more common outcome (~70–72% league-wide), so its marginal value is scaled by the smaller offensive-rebound rate; an offensive rebound is rarer and more valuable, scaled by the larger defensive-rebound rate.

3.3 Aggregation

The eight component terms add to the headline number:

$$ \texttt{valueAdd} = \texttt{vaPTSv} + \texttt{PTSAdd} + \texttt{vaAST} + \texttt{vaSTL} + \texttt{vaBLK} + \texttt{vaTOV} + \texttt{vaDRB} + \texttt{vaORB} $$

Per-game versions divide each term by G. Tab 8’s “Value Breakdown” renders the eight components stacked next to valueAdd itself, giving the reader an immediate visual decomposition of where a player’s value comes from.

Three formula variants and graceful fallback The codebase defines three nested variants — valueAdd_1, valueAdd_2, valueAdd_3 — and selects the most data-rich one available with coalesce(). Variant 1 is the full formula. Variant 2 omits the turnover term (used for seasons 1974–77, when STL/BLK are present but TOV measurement was inconsistent). Variant 3 omits turnovers, steals, and blocks and uses estimated rebound splits (used for 1952–73, before STL/BLK were tracked). This staged fallback is what allows the framework to extend back to 1949–50 without falsely punishing players for unrecorded events.

3.4 Eligibility, edge cases, and the games-played floor

  • Games-played floor (gpl). For per-game leaderboards, the app applies a games-played floor of $0.75 \cdot \max(G)$ in the season — roughly equivalent to the NBA’s 58-game qualification rule for 82-game seasons. For playoff comparisons (Tab 7.5), the floor relaxes to $0.5 \cdot \max(G)$ when the maximum is below 29, so that conference finalists and finalists are not the only eligible players.
  • Multi-team seasons. Players traded mid-season have a 5TM/4TM/3TM/2TM aggregate row that consolidates their statistics. The app uses the aggregate row for full-season computations and surfaces the constituent rows where relevant (e.g., the Career Comparison table).
  • Pre-1973 turnovers and pre-1974 steals/blocks. See the fallback variants above. The Four Factors view is gated to seasons after 1979–80, when the NBA introduced the three-point line, because pre-1980 efficiency profiles are structurally non-comparable.
  • Single-game value added. When the app ingests a live box score (Tabs 4–6, Game Lookup, Date Lookup), it joins the current season’s league baselines onto every game row. Game-level value added therefore answers “in this game, what did this player produce above an average minute of this season?” rather than baking in any historical context.

4. The six tabs #

The app exposes six top-level tabs. The order below matches the navbar order. Each section gives the inputs, the outputs, and a list of conclusions a user can credibly draw from the view — together with notes on conclusions the view does not license.

Tab 01 · Active comparison

Player Comparison

An active, head-to-head view comparing two players over arbitrary time windows. Game logs are scraped live from Basketball-Reference, the Value Added components are recomputed per game, and the user can roll up the result into a rolling-average trend, a windowed summary, or a single-game decomposition.

Inputs

  • Player 1 and Player 2 (free-text search; matches against the season totals roster)
  • Independent date ranges for each player
  • Statistic to track (defaults to Value Added; any column from menu_options.csv is selectable)
  • Rolling-average window length (in games)
  • Per-game vs. total toggle

Outputs

  • Rolling-average line plot — the chosen stat over each player’s game sequence, with team-color lines and date labels at the endpoints and at the peak game
  • Top-3 single-game performances table for each player, with VA decomposed into PTS, TRB, AST, BLK, STL, X3PAdd, X2PAdd+FTAdd
  • Window summary tables — G, MP, PTS, TRB, AST, 3P%, 3PA, FG%, STK aggregated over the chosen range and over the rolling-window tail
  • Single-game value-added breakdown — a horizontal diverging bar chart for any selected game, decomposing that game’s valueAdd into all ten point-equivalent components (Scoring Volume, 3P/2P/FT Efficiency, Assists, Steals, Blocks, Turnovers, DRB, ORB)

Conclusions you can draw

  • Form vs. baseline. Whether a player is currently performing above or below their season-long norm, on any chosen metric, with the rolling window setting the bandwidth.
  • Head-to-head trajectory. Which of two players is trending up, which is trending down, and where their lines cross during the window.
  • Peak driver. For any star performance, which Value Added component carried the night — whether a 35-point game was driven by efficiency (positive 3P/2P/FT Add) or by raw volume (positive vaPTSv on average shooting), and whether turnovers or rebounds shaved off value.
  • Comparable role read. For two players within similar minutes, the Window Summary makes role differences (creator vs. finisher; primary vs. secondary playmaker) visible across multiple stat lines simultaneously.

Conclusions this view does not license

  • Anything about defensive impact off-ball — the box-score events captured (STL, BLK) are a small fraction of true defensive value. A player’s on-ball defense, screen navigation, and rotational discipline are invisible here.
  • Lineup or matchup conditional inferences — the data is player-aggregated; teammate context is not.
Tab 02 · The flagship comparison

Four Factors Comparison

The app’s most analytically dense view. Two player-seasons are placed inside the entire league’s scatter plot of qualifying peers, on four orthogonal axes that together describe almost everything a player does on a basketball court. Every dot is a real season; the highlighted player-seasons are labeled and colored by their team’s primary hex.

Inputs

  • Player 1 and Year 1
  • Player 2 and Year 2 (the two seasons can be from the same year for direct head-to-head, or from different eras for cross-temporal comparison)

The four factors

  1. Scoring efficiency vs. volume. $x = \texttt{vaPTSv}/G$, $y = \texttt{PTSAdd}/G$. Upper-right is “high-volume and efficient”: the rare territory where superstars live.
  2. Playmaking vs. ball security. $x = \texttt{vaTOV}/G$ (sign-flipped so right = better), $y = \texttt{vaAST}/G$. Distinguishes pure passers, low-mistake handlers, and high-assist/high-turnover engines.
  3. Defensive events vs. rebounding. $x = (\texttt{vaORB} + \texttt{vaDRB})/G$, $y = (\texttt{vaSTL} + \texttt{vaBLK})/G$. Locates rim protectors, stocks-heavy guards, and glass-only bigs.
  4. Shot diet split. $x = (\texttt{PTSAdd} - 3 \cdot \texttt{X3PAdd})/G$ (interior + foul-line value), $y = 3 \cdot \texttt{X3PAdd}/G$ (perimeter value). Reveals whether a player’s scoring edge is paint/foul or perimeter.

Outputs

  • Four scatterplots arranged via patchwork, each with a regression line through the league cloud, the two highlighted player-seasons labeled and team-colored, and zero on every axis explicitly relabeled “League Average.” The player’s annotation includes a one-line read of the underlying box-score numbers (PPG, eFG%, APG, TOV/G, etc.) so the geometric position has a numeric anchor.

Conclusions you can draw

  • Quadrant identity. Each panel partitions the league cloud into four quadrants whose meanings are stable: e.g., upper-right of panel 1 is “high-volume and efficient scorer,” upper-left of panel 2 is “passes a lot but coughs the ball up.” A player’s identity emerges as the joint position across all four panels.
  • Star detection. A true star is far from the regression line on multiple panels at once. A specialist dominates a single panel and sits on the regression line elsewhere.
  • Cross-era comparison. Because every dot is z-scored against its own season’s league cloud, a 1985 season can be compared to a 2025 season meaningfully — the question is “how did each player rank against their contemporaries?” not “who put up bigger raw numbers?”
  • Shot-diet diagnosis. Panel 4 cleanly separates perimeter-driven scorers (high y, near-zero x) from interior/foul-line scorers (high x, near-zero y) from balanced threats (positive on both). Useful for evaluating fit, role, and projection.

Conclusions this view does not license

  • The panels are orthogonal by design but they are not exhaustive: off-ball gravity, screen-setting, and free-throw drawing are not represented.
  • The qualifying-games threshold (gpl) prunes the cloud; star players who missed substantial time will not appear at all.
Tab 03 · Season leaders

Leaderboard

A league-wide ranking view. The user picks a season and a statistic and the app returns the top of the leaderboard, optionally compared against a second season’s distribution. A neighborhood lookup surfaces the players adjacent to a chosen subject in the standings, and a team lookup returns a team’s rotation by minute load.

Inputs

  • Season (regular season or playoffs)
  • Statistic to rank by — default Value Added; any column from menu_options_2.csv is selectable
  • Per-game vs. total toggle
  • Optional second season for distribution comparison
  • Optional player or team for context lookup

Outputs

  • Top-10 leaders bar chart — horizontal bars colored by team hex.
  • Two-season facet plot — the same top-10 view side-by-side for two seasons.
  • Distribution comparison — bootstrap-resampled densities of 5-player-mean values for each season, overlaid with a strip showing where the top 10 sit. This answers the “was this year deeper or shallower than that one?” question.
  • Neighborhood table (lesearch) — the five players above and five below the user’s chosen subject, with each rate stat tagged “+” or “−” relative to league per-minute average and a z_s z-score on per-game value added.
  • Team rotation table (tesearch) — the team’s top 10 by minutes, each player’s per-game value added, and league-wide percentile.

Conclusions you can draw

  • Who led the league. Trivially — on any individual stat or any Value Added component — the top of the bar chart is the leader.
  • Era depth. The bootstrap distribution comparison gives a falsifiable answer to “was 2017’s top-10 stronger than 2024’s?” The strip shows where the realized leaders sit inside each year’s bootstrap density — far-right outliers indicate deep top-end talent.
  • Neighborhood comps. The lesearch table is the natural tool for “who else had the kind of year Player X had?” and exposes the rate-stat profile that placed each comparable on the leaderboard.
  • Team rotation reads. tesearch shows whether a team relies on a top-heavy two-man rotation or a balanced eight-deep group, in points-equivalent terms.
Tab 04 · Single-game by team

Game Lookup

Selects a single regular-season game from a team’s schedule and renders its full box score, the per-player Value Added breakdown, and a scatter plot of +/- versus Value Added that visualizes the relationship between on-court margin and individual production.

Inputs

  • Team (mapped to its Basketball-Reference abbreviation)
  • Season
  • Game (chosen from that team’s schedule, with opponent label)
  • Player (chosen from the box score for the per-player breakdown)

Outputs

  • Sortable box score table — every player from both teams with MP, PTS, TRB, AST, BLK, STL, TOV, FG/FGA, 3P/3PA, VA (game-level value added), and +/-, sorted by VA.
  • Single-player Value Added breakdown — the same ten-component diverging bar chart as in Tab 1, scoped to one player and one game.
  • Plus/minus vs. Value Added scatter — every player from the game placed in the (PM, VA) plane, with reference lines at zero on both axes. Selected team in team-color, others in grey.

Conclusions you can draw

  • Stat-line vs. impact divergence. The four quadrants of the PM×VA plane each tell a story:
    • Upper-right (high VA, positive PM): the player put up a strong stat line and the team won their minutes — clean positive performance.
    • Upper-left (high VA, negative PM): the player produced individually but the team lost their minutes — suggests the supporting cast struggled or the defense carried.
    • Lower-right (low VA, positive PM): the player did not show up in the box score but the team won their minutes — suggests an off-ball or defensive contribution invisible to the framework, or simply that the player benefited from teammates.
    • Lower-left (low VA, negative PM): a struggle on both axes.
  • Drivers of a single performance. The breakdown bar chart shows in points-equivalent units exactly which categories produced or destroyed value — a 28-point night with negative vaTOV and zero PTSAdd is a different game than a 22-point night on +5 efficiency.
  • Best player on the floor. The VA-sorted box score is a defensible answer to “who had the best statistical game” that subsumes both volume and efficiency.
Tab 05 · Single-game by date

Date Lookup

The complement to Game Lookup. Where Game Lookup walks down a single team’s schedule, Date Lookup walks down the league’s entire slate for a chosen day — both regular season and playoffs — and lets the user drill into any matchup. It also subsumes the “yesterday’s games” functionality from the source-tab structure.

Inputs

  • Date (any day with NBA action, defaulting to recent)
  • Matchup (any game from that day)
  • Period filter (full game, by quarter, by half, by overtime)
  • Player (chosen from the box score for the per-player breakdown)

Outputs

  • Day’s slate — every game played on that date with hyperlinks to box scores.
  • Period-filterable box score — full game or any subset, with cleaned-up minute formatting.
  • Top-10 performances on the date — a ranking across the entire slate, ordered by Value Added, scattered against +/- with the same axis convention as Tab 4.
  • Player breakdown — the same ten-component diverging bar chart for any player picked from the slate.

Conclusions you can draw

  • Best night in the league. Across every game on the slate, who produced the most value — a single ranking that crosses team boundaries.
  • Period-specific reads. A 22-point quarter and a 4-point fourth are different stories. The period filter exposes within-game drift.
  • Slate-wide quadrant scan. The top-10 PM×VA scatter for a single date often makes the “empty-stats” or “invisible-impact” players visible at a glance.
Tab 06 · Career arc

Career Comparison

A side-by-side career table for two players, with each season ranked league-wide by the chosen metric and color-shaded by rank. Sub-views switch between regular-season careers and playoff careers (the latter relaxes the games-played floor for short series).

Inputs

  • Player 1 and Player 2
  • Statistic (default Value Added)
  • Per-game vs. total toggle
  • Regular season vs. playoffs sub-view

Outputs

  • Mirrored career table. Player 1 columns reversed on the left, Player 2 on the right, blank spacer column in the middle. Each season row shows: Value (Rank), Year — or Year (G) for playoffs — Team, PTS/TRB/AST/STK rate stats, and FG%/3P%/FT% shooting splits. The Value cell is shaded by season rank, with darker team-color for top-of-league seasons. Rank carries an ordinal suffix (“1st”, “2nd”, “3rd”, “9th”).

Conclusions you can draw

  • Career shape. The visual gradient of color saturation across rows immediately communicates whether a career was peak-and-decline, late-blooming, plateau-then-collapse, or sustained-elite.
  • Peak height. A “1st” or “2nd” rank in the Value column is an MVP-caliber season by the framework’s lights. Multiple top-5 seasons indicate a sustained All-NBA tier.
  • Longevity vs. peak. Two players with similar career totals but different shapes (more medium-quality seasons vs. fewer elite seasons) read differently on the table.
  • Playoff differential. Toggling the playoff sub-view exposes players who outperform their regular-season ranks in the postseason and those who collapse, accounting for short-series sample size via the relaxed floor.
  • Stat-line context for the rank. The accompanying rate stats and shooting splits guard against framework artifacts — a high VA rank produced by extreme efficiency at low volume reads differently from one produced by extreme volume at average efficiency.

5. A worked example #

To make the framework concrete, consider a stylized stretch big in the modern NBA — call him Player A — with the following per-game profile in a season where the league averages are laPTSperM = 0.45, laASTperM = 0.10, laSTLperM = 0.027, laBLKperM = 0.020, laTOVperM = 0.045, laDRBperM = 0.135, laORBperM = 0.040, la3P. = 0.367, la2P. = 0.547, laFT. = 0.785, laFG. = 0.470, laPTSperPoss = 1.13, laPTSperMake = 2.27, laDRBrate = 0.72, laORBrate = 0.28:

Player A, 70 games, 28.0 MPG — 14.5 PTS, 7.0 TRB (5.4 DRB / 1.6 ORB), 1.8 AST, 0.9 STL, 1.7 BLK, 1.2 TOV, on 41.5% from three (5.0 3PA), 56.0% from two (4.4 2PA), 78.0% from FT (2.5 FTA).

Per-season totals: MP = 1960, PTS = 1015, 3P = 145.25, 3PA = 350, 2P = 172.48, 2PA = 308, FT = 136.5, FTA = 175.

Step 1 — Volume scoring

$\texttt{vaPTSv} = (1015/1960 - 0.45) \cdot 1960 = (0.518 - 0.45) \cdot 1960 \approx 133.3$ points.

The player scored ~133 points more than a league-average minute would have produced over those 1960 minutes.

Step 2 — Shooting efficiency

$\texttt{X3PAdd} = (0.415 - 0.367) \cdot 350 = 16.8$ extra makes → 50.4 points ($\times 3$).

$\texttt{X2PAdd} = (0.560 - 0.547) \cdot 308 = 4.0$ extra makes → 8.0 points ($\times 2$).

$\texttt{FTAdd} = (0.780 - 0.785) \cdot 175 = -0.9$ extra makes → −0.9 points.

$\texttt{PTSAdd} \approx 50.4 + 8.0 - 0.9 = 57.5$ points.

Step 3 — The rest of the components

Working through the per-minute formulas with the rates above:

  • $\texttt{vaAST} = (1.8/28 - 0.10) \cdot 1960 \cdot 2.27 \cdot (1 - 0.470) \approx -41.0$ — below-average passing for the position, costing ~41 points.
  • $\texttt{vaSTL} = (0.9/28 - 0.027) \cdot 1960 \cdot 1.13 \approx 12.0$ — modest positive.
  • $\texttt{vaBLK} = (1.7/28 - 0.020) \cdot 1960 \cdot 1.13 \cdot 0.72 \approx 64.0$ — strong rim protection at 1.7 BPG.
  • $\texttt{vaTOV} = -1 \cdot (1.2/28 - 0.045) \cdot 1960 \cdot 1.13 \approx 5.6$ — very slightly below average turnovers, a small positive.
  • $\texttt{vaDRB} = (5.4/28 - 0.135) \cdot 1960 \cdot 1.13 \cdot 0.28 \approx 36.5$.
  • $\texttt{vaORB} = (1.6/28 - 0.040) \cdot 1960 \cdot 1.13 \cdot 0.72 \approx 27.5$.

Step 4 — Aggregate

$\texttt{valueAdd} \approx 133.3 + 57.5 - 41.0 + 12.0 + 64.0 + 5.6 + 36.5 + 27.5 = \mathbf{295.4}$ points.

Or, per game, ~4.2 points added. In the language of Tab 8, the bar chart for Player A would render as:

A floor-spacing five who anchors a defense reads exactly the way the framework should expect such a player to read.

What this earns you The decomposition is what makes Trey’s NBA Stats Stuff different from a single-number metric. PER will tell you Player A had a 22.0 season; BPM might say +3.5; Win Shares might say 8.4. None of those tell you that the player’s edge is volume + defense + glass and that a passing upgrade is the obvious place to grow. The Tab 8 view does, on a single chart, with units anyone in basketball understands.

7. Data & pipeline #

Sources

  • Season totals. Scraped per-year from basketball-reference.com/leagues/NBA_<year>_totals.html for the regular season and playoffs separately, then concatenated.
  • Shooting distance splits. Scraped from NBA_<year>_shooting.html from 1996–97 onward; older seasons get NA-padded shooting splits and fall through to the appropriate valueAdd_* variant.
  • Live game logs. Scraped per-player from Basketball-Reference player pages on demand for any tab that requires within-season game-by-game information.
  • Live box scores. Scraped from the boxscore pages and the “daily” index for date-based views.
  • Team colors. Maintained statically in Complete Data/team_hex_colors.csv.

Refresh and caching

The bootstrap routine (totals_collect.R) writes a dated daily snapshot to Complete Data/Totals_s_<DATE>.csv and Complete Data/Totals_p_<DATE>.csv the first time the app is opened on any given day. Subsequent invocations on the same day re-use the snapshot, so the app responds instantly. League-baseline summaries are written to Complete Data/avgsSummary.csv in the same step.

Per-game recomputation

Game-log views recompute the Value Added components on the fly: each game row is joined to the current season’s row in avgsSummary.csv and the formulas in §3.2 are evaluated with that game’s box-score statistics. This keeps the live view exactly consistent with the season-level decomposition while letting the user drill into individual nights.

8. Limitations #

  1. Box-score floor. The framework can only see what the box score records. Off-ball defense, screen quality, gravity, deflections (until very recently), and most communication-based contributions are invisible. A player whose value is concentrated in those areas will be systematically undercounted.
  2. Assist credit is opinionated. The $(1 - \texttt{laFG.})$ marginal factor is a defensible choice but not the only defensible choice. A reader who prefers a different counterfactual (say, a flat 2-point credit per assist, or a 0.5 marginal factor) should mentally rescale vaAST; everything else is unaffected.
  3. Rebound attribution is also opinionated. Crediting a rebound as “a possession the team would have lost” via the opposite-end rebound rate is one model; team-level rebound chains and contested-vs.-uncontested adjustments would refine it.
  4. Per-minute baselines do not adjust for pace, role, or position. A high-pace era inflates every counting stat; the framework controls for this in its cross-season comparison (every player is z-scored against their own season) but a within-season comparison still mixes high-pace and low-pace teams without adjustment.
  5. Pre-1974 fallback. Variant 3 of the formula uses estimated rebound splits and omits steals/blocks/turnovers because they were not recorded. Pre-1974 valueAdd values are therefore comparable among themselves but should not be put on the same axis as modern values without caveat.
  6. Basketball-Reference source dependence. Any change in HTML structure or rate-limiting at the source can break the daily refresh until the scraper is updated.
  7. The framework measures one number very well, but not every number. Defensive rating, on/off splits, lineup-adjusted plus/minus, and tracking-derived metrics are complements to valueAdd, not substitutes. The intended use is “valueAdd first, then triangulate.”

9. Extensions & future work #

  • Position- and role-conditional baselines. Replacing league-wide medians with position-conditional medians (or with usage-bucketed baselines) would allow the framework to ask “above average for this kind of player” rather than “above average for any player.” This is a one-table change in avgsSummary.csv.
  • Possession-level pace adjustment. Multiplying per-minute baselines by a team-relative pace factor would normalize 1980s vs. 2020s comparisons within the framework rather than only via the rank-based Career Comparison view.
  • Tracking-data integration. Adding gravity, defensive matchup time, and screen-assist data from Second Spectrum / NBA Stats would close the “invisible defense” gap explicitly. The Tab 8 bar chart would gain rows for “Off-ball Gravity Added,” “Matchup Defense Added,” etc.
  • Lineup-conditional decomposition. Splitting valueAdd by the lineup the player was on the floor with would let the user separate a player’s individual production from teammate-driven production in a defensible way.
  • Bayesian shrinkage on small samples. Particularly relevant for playoffs and for early-season game-log views, where 5-game samples are noisy. Shrinking each component toward the player’s season-long mean would give better in-window estimates.
  • Public release of the season-level dataset. The Complete Data/Totals_s_*.csv and Totals_p_*.csv files are independently useful research datasets and could be published on a versioned cadence.
